# Сайт модуля Жана Моне EU-HERITAGE

Двомовний (українська / англійська) сайт проєкту 101322435 «EU Approaches to Heritage-Based Urban Planning and Regeneration», КНУБА. Результат D1.5 (Project Website), запуск у M4.

Технічна схема: вміст зберігається у файлах цього репозиторію (папка `content/`), команда редагує його через **Pages CMS** у браузері, а **GitHub Actions** після кожної зміни збирає сайт генератором Eleventy і публікує на **GitHub Pages**. Усе безкоштовно.

---

## Частина 1. Для адміністратора: запуск сайту

### Крок 1. Організація і репозиторій на GitHub

1. Зареєструйтеся або увійдіть на github.com.
2. Створіть організацію (аватар угорі праворуч → **Your organizations → New organization**, безкоштовний план), наприклад `knuba-eu-heritage`. Організація потрібна, щоб сайт не залежав від акаунта однієї людини після завершення проєкту.
3. В організації створіть репозиторій **New repository** → назва `eu-heritage-site` → **Public** → **Create repository**.

### Крок 2. Завантаження файлів

1. Розпакуйте архів `eu-heritage-site.zip` на комп'ютері.
2. У репозиторії натисніть **uploading an existing file** (або **Add file → Upload files**).
3. Перетягніть **усі файли й папки з розпакованої папки** (не саму папку). Приховані файли `.pages.yml`, `.gitignore` і папка `.github` обов'язкові: у Windows увімкніть показ прихованих файлів, у macOS натисніть Cmd+Shift+. у Finder.
4. Натисніть **Commit changes**.

Перевірка: у корені репозиторію мають бути `.github`, `content`, `media`, `src`, `.pages.yml`, `package.json`, `package-lock.json`, `eleventy.config.js`, `README.md`.

### Крок 3. Увімкнення публікації

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Відкрийте вкладку **Actions**. Якщо збірка ще не запускалася, оберіть **Publish site → Run workflow**.
3. Через 1–2 хвилини сайт буде доступний за адресою `https://knuba-eu-heritage.github.io/eu-heritage-site/`.

Зелена позначка в **Actions** означає, що збірка пройшла. Червона — що є помилка; відкрийте запуск і подивіться повідомлення (найчастіше це синтаксична помилка у файлі з `content/`, якщо його редагували вручну).

### Крок 4. Підключення Pages CMS

1. Відкрийте https://pagescms.org і натисніть **Sign in** → увійдіть через GitHub.
2. Pages CMS запропонує встановити свій GitHub App. Встановіть його для організації `knuba-eu-heritage` і надайте доступ лише до репозиторію `eu-heritage-site`.
3. Відкрийте репозиторій у Pages CMS. Ліворуч з'являться розділи: Події, Новини, Policy briefs, Випуски, Ресурси, Команда, сторінки й Налаштування сайту.

### Крок 5. Запрошення команди

У Pages CMS: **Collaborators** (у налаштуваннях репозиторію) → введіть email колеги → **Invite**. Колега отримає лист і входитиме за посиланням з пошти, без акаунта GitHub. Запрошені співавтори можуть редагувати вміст і файли, але не змінюють `.pages.yml` і не керують іншими співавторами.

### Крок 6. Власний домен (коли ІТ-відділ буде готовий)

1. ІТ-відділ КНУБА додає DNS-запис: `eu-heritage.knuba.edu.ua` типу **CNAME** → `knuba-eu-heritage.github.io`.
2. У репозиторії: **Settings → Pages → Custom domain** → `eu-heritage.knuba.edu.ua` → **Save**. Після перевірки DNS увімкніть **Enforce HTTPS**.
3. Запустіть збірку ще раз (**Actions → Publish site → Run workflow**). Адреси сторінок перебудуються без префікса `/eu-heritage-site/` автоматично.
4. Бажано також підтвердити домен в організації (**Organization settings → Pages → Add a domain**), щоб його не могли використати інші акаунти.

## Частина 2. Для редакторів: щоденна робота

### Загальний принцип

1. Відкрийте Pages CMS за посиланням з листа-запрошення.
2. Оберіть розділ ліворуч, відкрийте запис, змініть поля, натисніть **Save**.
3. Через 1–2 хвилини зміни з'являться на сайті.

Кожне текстове поле має дві половини: **Українською** і **English**. Якщо англійську не заповнено, на англійській версії сайту показується українська — сторінка не буде порожньою, але варто перекласти.

Поле **Чернетка** ховає запис із сайту. Зручно, щоб підготувати подію чи новину заздалегідь.

Поле **Адреса сторінки** (латиницею через дефіс) стає частиною посилання, наприклад `.../events/webinar-3-integrated-development/`. Після публікації його не змінюйте, інакше старі посилання перестануть працювати.

### Як оголосити подію

1. **Події** → відкрийте потрібний запис (усі 9 заходів уже створено).
2. Уточніть дату, зніміть «Дата орієнтовна», вкажіть час і формат.
3. Заповніть **Анонс** і **Програму** (спікери, теми, порядок).
4. Вставте **Посилання на форму реєстрації** (Google Forms, Microsoft Forms тощо). Кнопка «Зареєструватися» з'являється автоматично, поки подія не відбулася.
5. **Save**.

### Що зробити після події

Сайт сам перенесе подію в «Відбулися» наступного дня. Далі заповніть у тому ж записі:

- **Кількість учасників.** Число одразу додається до показника «Зовнішніх учасників» на головній, а подія зараховується до лічильника вебінарів чи конференцій.
- **Звіт** — кілька абзаців про те, що відбулося.
- **Посилання на запис** (YouTube тощо; увімкніть субтитри).
- **Матеріали** — презентації, підсумок фідбеку. Кнопка «Add» додає новий рядок.

Ці блоки відповідають пакету документів для D1.4 (запрошення, програма, звіт, матеріали, підсумок фідбеку). Підписаний список присутніх на сайт **не** викладайте — він лише для звітності.

### Як додати новину

**Новини → Add entry** → заповніть адресу, дату, заголовок, короткий опис, текст → **Save**. Для зображення завжди заповнюйте «Опис зображення для незрячих».

### Як додати policy brief

1. Спершу отримайте від студента письмову згоду на публікацію за ліцензією CC BY 4.0.
2. **Policy briefs** → **Add entry** (запис «Приклад…» показує, як заповнювати поля).
3. Заповніть назву, автора, рік, теми, місто, анотацію; завантажте PDF.
4. Якщо бриф увійшов до випуску серії, оберіть номер випуску; якщо отримав нагороду — позначте **Student Policy Brief Award**.
5. Зніміть **Чернетку** → **Save**.

### Як опублікувати випуск Policy Brief Series

**Випуски Policy Brief Series → Add entry** → номер (1, 2 або 3), дата, назва, опис, PDF → **Save**. Плани: випуск 1 — M12, випуск 2 — M24, випуск 3 — M34.

### Після кожного навчального циклу

**Налаштування сайту → Студентів пройшли курс** → введіть загальну кількість (накопичувально: після першого циклу ~50, після другого ~100 тощо).

### Файли

PDF та інші документи потрапляють у папку `media/files`, зображення — у `media/images`. Великі відео не завантажуйте на сайт — публікуйте на YouTube і вставляйте посилання. Перед завантаженням називайте файли латиницею: `policy-brief-series-issue-1.pdf`.

## Частина 3. Технічна довідка

### Структура

```
.pages.yml               форми Pages CMS (що бачать редактори)
content/                 увесь вміст сайту (YAML)
  settings/site.yml      налаштування, контакти, показники
  pages/*.yml            окремі сторінки
  events/ news/ briefs/ issues/ resources/ team/
media/                   завантажені зображення та документи
src/                     шаблони, стилі, шрифти, скрипти
  _data/i18n.js          написи інтерфейсу двома мовами
  _data/db.js            читання вмісту, лічильники показників
  assets/css/site.css    стилі
.github/workflows/deploy.yml   збірка і публікація
```

### Локальний перегляд

Потрібен Node.js 20 або новіший.

```bash
npm install
npm start        # сайт на http://localhost:8080/uk/
npm run build    # готовий сайт у папці _site/
```

Перевірити, як сайт виглядатиме на певну дату (наприклад, які події вже «відбулися»):

```bash
BUILD_DATE=2028-01-15 npm start
```

### Щоденна перезбірка

Робочий процес `deploy.yml` запускається після кожної зміни і щоночі о 03:15 UTC, щоб статус подій оновлювався без втручання. Якщо в репозиторії 60 днів не було змін, GitHub вимикає запуски за розкладом; тоді увімкніть їх знову у вкладці **Actions**.

### Приватність

Сайт не використовує cookies і аналітику. Шрифти (Literata, IBM Plex Sans; ліцензія SIL OFL) розміщено на самому сайті, тож браузер відвідувача не звертається до сторонніх серверів. Якщо згодом підключатимете аналітику, оновіть сторінку «Конфіденційність».

### Якщо Pages CMS показує помилку конфігурації

Файл `.pages.yml` написано за документацією Pages CMS (pagescms.org/docs). Якщо сервіс повідомляє про помилку, найімовірніші місця — поля-списки (`list: true`) і поля з `component`. Скопіюйте текст помилки й виправте відповідний фрагмент; вміст у `content/` при цьому не постраждає.

### Сталість після M36

Уся інформація — звичайні текстові файли в репозиторії організації. Щоб передати сайт іншій команді, достатньо додати нових людей до організації GitHub і до співавторів Pages CMS. Остаточні версії документів також депонуйте в інституційний репозитарій КНУБА, як передбачено в заявці.
